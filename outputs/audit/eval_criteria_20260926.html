R판정 원칙 — 모델·알고리즘을 바꿀 때 공통으로 적용

  • 같은 데이터, 같은 정답, 같은 스크립트로 잰 값끼리만 비교한다. 프레임 수·소스 필터·임계값이 다르면 표에 같이 적지 않는다.
  • 정밀도와 재현율은 항상 같이 적는다. 오병합(정밀도↓)과 과분할(재현율↓)은 맞바꿈 관계라 한쪽만 좋아진 결과는 개선이 아니다. 노이즈 비율 단독 보고 금지.
  • 개선 폭이 재현성 잡음보다 커야 한다. Leiden 은 seed 를 바꿔도 쌍 F1 변동 ≤ 0.002 (seed 42/1/777 실측) → 클러스터링은 Δ ≥ 0.01 부터 유의미로 본다. 검출은 300 프레임 값이 아니라 test 전체 6,112 프레임 값으로 판정한다.
  • 운영 동작점을 명시한다. 검출 임계값(운영 0.5 / 영상 0.2), 클러스터 임계값(0.97), 후보 수(200) 를 바꾼 비교는 "설정 변경"이지 "모델 교체"가 아니다.
  • 속도는 제약 조건이다. 정확도가 같으면 빠른 쪽, 정확도가 낮으면 속도로 만회하지 않는다 (제약: 검출 ≥ 10 fps@1080p, 검색 1건 ≤ 3 s 모델 로드 제외).
  • 결과 파일에는 사용한 조합을 pipeline/models(검색), detector(검출 checkpoint), plugin(클러스터 report) 필드로 남긴다 — 표의 숫자는 그 파일에서 나온 것이어야 한다.

2추적 · 스티칭 (Tracking · Stitching)

현재 GT 가 없어 미측정. 트랙 품질 리포트(build_track_quality_report 계열)는 길이·단절 통계만 있고 정답 대조가 없다. 아래는 채택 전에 갖춰야 할 지표와 정답 확보 방안.

P6 (09-28) 도구 준비: eval/track_gt_eval.py sheet 가 영상별 준정답 시트(eval/gt/tracks/<영상>/sheet.html, 썸네일 내장)를 만들고 eval 이 labels.json 으로 raw(추적기 id)/before(구간)/after(긴 트랙)의 IDF1·HOTA·MOTA·IDSW·단절·갈라짐·과병합을 낸다 (원장 stage=track). 시트 3편(048·289·100: 구간 116, 긴 트랙 77 중 person 54) 라벨링 대기. 실측 주의: 추적기 id 는 시간이 지나면 재사용되고(한 id 가 5 명), SUSHI 는 512 프레임 창을 독립 처리해 같은 사람이 창마다 다른 긴 트랙 id 를 받는다 (048 영상의 정지 박스 하나가 L1·L8·L18·L28) — 라벨이 붙으면 after 의 splits/IDSW 로 정량화된다. pseudo(제안값 = 정답 가정) 실행(09-28 초판 지표): raw IDF1 0.585 / before 0.931 / after 0.998, IDSW 96 / 105 / 0. 외부 검토(Astra, 09-28 16:09) 반영: HOTA·CLEAR·ignore 를 TrackEval 정의로 재구현(프레임당 매칭 1회 후 α 필터, 직전 프레임 우선 매칭, MOTChallenge ignore), before 를 스티처와 무관한 추적기 tracklet 로 정의, 라벨 검토 체크·검토율·manifest 도입(제안값 승격 방지, 시트 재생성 시 옛 라벨 거부), 채택 판정에 incomplete(지표 누락·기준값 미정 = 확인 불가) 추가, Qwen 은 불변 후보 id 로 라벨 연결·filter 를 평가기에서 재현·캐시 계약(<qid>.meta.json)·오탈락률 두 정의, 객체는 캐시 정합성 검사·없는 트랙 쌍 제외·모순 보고·point 목록 보존. SUSHI 창 경계 연결 후처리(pipeline_tracking_sushi_link.yaml, raw track 연속 + IoU + 일대일)를 추가해 러너로 비교 가능. 창 경계 연결(restitch, 같은 검출·추적 출력, 3편 pseudo GT = 추적기 연속성 기준): 원 스티처 after IDF1 0.619 / IDSW 41 / 갈라짐 32 / 과병합 8 → 연결 후 IDF1 0.937 / IDSW 19 / 갈라짐 10 / 과병합 7 (048 긴 트랙 34→16, 289 26→18, 100 16→12; 거절된 후보는 간격 6·15·31 프레임). 사람 라벨이 붙어야 '같은 사람' 여부가 확정된다.

채택 기준 (새 임베더)

  • 이미지 쿼리용(사람): PRW mAP ≥ 89.1 이면 SOLIDER 대체 후보, 80 이상이면 조합 후보. 그 미만은 채택하지 않는다.
  • 텍스트 쿼리용: supports_text: true 이고 PRW mAP ≥ 58.6 (IRRA) 이면 1차 후보 교체 검토. SigLIP2 수준(12.4)은 속성 검색 보조로만 쓴다.
  • 차원이 다르면 새 collection_prefix 로 별도 적재 후 비교한다 (기존 컬렉션과 named vector 차원 충돌).
  • 객체 임베더는 정답이 없으므로 채택 전 소규모 객체 identity 세트(같은 물건 재출현 50쌍 이상) 라벨링이 선행돼야 한다.

채택 기준 (조합 변경)

  • mAP 상승 그리고 pool recall ≥ 90 % (후보 단계에서 정답을 잃지 않을 것). Rank-1 은 이미 97 % 근처라 판정 기준으로 쓰지 않는다.
  • 영상 검색(track 그룹)은 정답이 없다. 현재 쓸 수 있는 지표는 Top-10 안의 서로 다른 그룹 수(30 쿼리 평균): 기본 2.5 → 클러스터 묶기 7.7 — 중복 억제 효과만 보여 주며 정답성은 말하지 않는다. 채택 판정에는 트랙 준정답(§2)이 필요하다.
